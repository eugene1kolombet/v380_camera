# v380pull — скачивание записей с камеры V380 Pro по локальной сети

Протокол восстановлен из декомпилированного SDK приложения **V380 Pro 2.2.90**
(`com.macrovideo.sdk`). Инструмент работает с вашей камерой в вашей локальной
сети — это разбор протокола ради совместимости, а не обход защиты.

## Установка

```bash
pip install cryptography
```

Нужен Python 3.8+.

## Два пароля — не путать

На наклейке камеры (`IPC-V380-Q8`) есть поле **Password** — это пароль *самой камеры*
(вход в неё по сети). Пароль вашего Wi-Fi роутера — отдельная вещь, его камере
передают при настройке.

- `--password` = пароль камеры (с наклейки).
- `--wifi-password` = пароль роутера.

## Шаг 0. Подключить камеру к Wi-Fi (режим AP)

Пока камера не в вашей сети, ей нужно передать имя сети и пароль:

1. Сбросьте камеру в режим точки доступа: удерживайте Reset, пока она не скажет
   голосом, что готова к настройке (создаёт свой Wi-Fi, имя вида `MV…`).
2. Подключите **ПК** к этому Wi-Fi камеры.
3. Передайте ей вашу сеть:

```bash
python v380pull.py --password <пароль_камеры> provision --ssid <сеть> --wifi-password <пароль_wifi>
```

(камера в AP-режиме всегда по адресу `192.168.1.1`, порт 8089 — указывать не нужно).

4. Камера перезагрузится и подключится к вашей сети. Верните ПК в свою сеть и найдите её:
   `python v380pull.py discover`.

## Использование (камера уже в вашей сети)

```bash
# 1. Найти камеру в сети (или посмотреть её IP в роутере)
python v380pull.py discover

# 2. Показать записи за последние сутки
python v380pull.py --ip 192.168.1.50 --password <пароль_камеры> list

# то же за конкретный период и только тревоги
python v380pull.py --ip 192.168.1.50 --password ПАРОЛЬ list \
    --from "2026-10-20 00:00" --to "2026-10-24 23:59" --type 3

# 3. Скачать файл по пути (см. ниже про записи SD)
python v380pull.py --ip 192.168.1.50 --password ПАРОЛЬ \
    download-file --dfid <N> --vfp "<путь>" --out rec.dat
```

`--password` — пароль камеры в локальной сети (тот, что задан в приложении для
прямого подключения; на новой камере часто пустой или `admin`).

При любой проблеме добавьте `--debug` — программа печатает каждый пакет
(hex-заголовок и расшифрованный JSON). Это главный инструмент отладки на живой камере.

## Как устроен протокол (кратко)

1. **TCP** на порт **8089** (IoT-прошивки) либо **8800** (легаси).
2. **Обмен ключами X25519** (`METHOD_ID_IOTC_LANPASS`): шлём свой публичный ключ
   (XOR с magic-байтом) и `sha256(pub‖пароль)`; камера возвращает свой ключ,
   общий секрет X25519 = **ключ сессии**. В локальной сети это и есть вход.
3. Все пакеты: 16-байтный заголовок (little-endian) + JSON, зашифрованный
   **AES-128-CBC** (ключ = первые 16 байт секрета, IV = следующие 16).
4. **Список записей** (`REC_FILE_LIST`): `{filter,mode,start,end}` → сегменты
   `{s,d,t}` (смещение, длительность, тип).
5. **Скачивание файла** (`FILE_DOWNLOAD`): `{vfid,dfid,vfp,off}`, ответ — поток
   двоичных кусков, пишем в файл; `off` даёт возобновление.

## РАБОТАЕТ: скачивание видео в mp4

```bash
python v380pull.py --ip <IP> --password <пароль_камеры> download --seg 0 --out rec.mp4
```
Скачивает запись сегмента с SD-карты в проигрываемый mp4 (видео H.264 1280x720).
Шифр кадра — AES-128-CBC сессионным ключом, выборочно (см. PROTOCOL_NOTES.md «Проход 10»).
Аудио (codec 103) пока не муксится.

## Статус (проверено на живой камере IPC-V380-Q8, прошивка 2.2.90)

**Работает и подтверждено вживую:**

- Вход по LAN (обмен ключами X25519 + пароль камеры) — OK.
- Шифр пакета — **AES-128-CBC** (предположение подтвердилось: и запрос, и ответ
  камеры расшифровываются корректно).
- **Список записей** (`list`) — показывает все сегменты на SD-карте с временем,
  длительностью и типом. Важная деталь, уже учтена в коде: «все типы» = фильтр **15**,
  а не 0 (с 0 камера возвращает пустой список).

**Ещё не решено — скачивание самих видеофайлов.** На SD камера хранит не отдельные
mp4, а запись по времени, и отдаёт её **только через свой нативный протокол**
(`libhsMediaLibrary.so`, вызовы `startPlayback`/`startDownload`). Этого протокола нет
в декомпилированной Java — его параметры (поток кадров H.264, сборка в mp4) зашиты в
нативной библиотеке. `download-file` (generic FILE_DOWNLOAD) качает только именованные
файлы (снимки, аудио-подсказки), но не видеозаписи SD.

Чтобы получить сами видео, есть три пути:
1. **Реверс нативного протокола воспроизведения** (разбор `libhsMediaLibrary.so` или
   перехват трафика) — самый трудоёмкий, но даёт скачивание прямо программой.
2. **Вынуть microSD и прочитать на ПК** — самый быстрый; формат у V380 свой, при
   необходимости поможем сконвертировать.
3. **Включить ONVIF/RTSP** в настройках камеры (через уже рабочий протокол) и
   пробовать стандартные плееры — но SD-воспроизведение по ONVIF поддерживают не все
   модели (порт 554 на этой камере сейчас закрыт).

## Порядок на живой камере

1. `discover` → узнать IP (или взять из роутера).
2. `list` → видим записи на SD-карте.
3. Скачивание видео — по одному из трёх путей выше (в работе).
